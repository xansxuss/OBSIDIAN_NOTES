# 固定翼無人機高速目標追蹤系統 — 研究清單

硬體平台：Pixhawk（飛控）+ Jetson Orin NX（機載運算）+ 4G 模組（遙測/指揮頻道）

---

## 1. 飛控端（Pixhawk / ArduPilot or PX4）

- [ ] 決定用 ArduPilot 還是 PX4：兩者的 MAVLink 訊息集、EKF 版本（ArduPilot 用 EKF3、PX4 用 ECL/EKF2）、韌體客製化難易度都不同
- [ ] 研究 `MAV_CMD_SET_MESSAGE_INTERVAL`，確認 `ATTITUDE` / `ATTITUDE_QUATERNION` / `LOCAL_POSITION_NED` / `GLOBAL_POSITION_INT` 可以拉到多高頻率（實測，不是看文件標稱值）
- [ ] 確認 Pixhawk 型號的 IMU 規格（陀螺儀/加速度計雜訊密度、bias 穩定度），評估是否需要額外外部 IMU
- [ ] 研究 Pixhawk 與 Jetson 之間的實體連線方式：UART（TELEM port）vs. 乙太網路（若飛控支援），評估頻寬與延遲
- [ ] 研究飛控韌體的時間同步機制（`TIMESYNC` 訊息、PPS 訊號腳位是否存在）
- [ ] 確認固定翼在坡度轉彎（banking turn）時，EKF 姿態輸出的延遲與抖動特性（可能需要實際飛測記錄 log 分析）

## 2. Jetson Orin NX 機載運算

- [ ] 確認 JetPack / L4T 版本與 TensorRT、CUDA、cuDNN 版本相容性
- [ ] 評估 Orin NX 8GB 還是 16GB 版本足夠（模型大小 + 多執行緒記憶體用量）
- [ ] 研究功耗模式（15W / 25W / MAXN）對推論幀率的影響，並評估飛機電池/供電系統能否穩定供應
- [ ] 研究散熱方案：機艙氣流是否足夠，或需要主動散熱片/風扇（重量與可靠度的取捨）
- [ ] 確認相機介面（CSI vs. USB3 vs. GMSL），評估頻寬與飛控艙內走線
- [ ] 研究 Jetson 上 MAVLink 函式庫選擇：`pymavlink`（原型驗證用）vs. `MAVSDK`（C++/正式系統用）vs. 自己刻精簡版解析器

## 3. AI 偵測模型（機上即時推論）

- [ ] 比較 YOLOv8/v10/v11-nano、YOLO-NAS、RT-DETR 等模型在 Orin NX 上的 TensorRT 實測 FPS 與精度
- [ ] 研究小目標偵測（高速物體在畫面上通常佔比很小）的資料集增強與模型調整技巧（例如切 tile 偵測、高解析度輸入）
- [ ] 研究動態模糊（motion blur）對偵測準確率的影響，評估是否需要縮短相機曝光時間或用全域快門相機
- [ ] 研究模型量化（INT8/FP16）在 TensorRT 上的精度損失評估流程
- [ ] 蒐集或標註符合你目標場景（速度、大小、背景）的訓練資料集
- [ ] 研究偵測結果的信心值門檻設定，跟濾波器的量測雜訊 R 之間如何動態關聯（信心低時放大 R）

## 4. 座標系轉換與時間同步

- [ ] 研究機體座標（相機/雲台）→ 大地座標（NED/ECEF）的四元數轉換公式與數值穩定性
- [ ] 若有雲台：研究雲台角度回授（雲台自身編碼器 or 額外 IMU）與機身姿態的疊加方式
- [ ] 設計相機影格時間戳記（V4L2 硬體時間戳）與 Pixhawk 姿態時間戳的對齊機制
- [ ] 研究姿態資料的內插方法（球面線性內插 SLERP），讓任意曝光時間點都能算出對應姿態
- [ ] 評估角度量測（bearing-only）vs. 角度+測距（若有測距儀/立體相機）對濾波器可觀測性（observability）的差異

## 5. 狀態估計 / 濾波器設計

- [ ] 決定濾波器等級：EKF 夠用，還是需要 UKF（非線性程度高時 UKF 較穩健）
- [ ] 若目標會機動轉彎：研究 IMM（Interacting Multiple Model）多模型架構（等速模型 + 協調轉彎模型）
- [ ] 設計簡化版 OOSM（延遲量測回溯校正）的緩衝區大小，依「AI推論延遲上限 ÷ 高頻迴圈週期」估算
- [ ] 研究純角度追蹤（bearing-only tracking）在單一觀測平台下的可觀測性問題（通常需要觀測者自身機動才能收斂距離估計）
- [ ] 設計量測雜訊 R 的動態調整策略（依偵測信心值、目標在畫面上的大小/距離估計調整）
- [ ] 規劃離線 log 回放測試框架：把飛行紀錄的 IMU + AI 偵測結果離線重播，驗證濾波器參數調校

## 6. 軟體架構 / 即時系統設計

- [ ] 設計執行緒切分：MAVLink IO / 相機擷取+推論 / 高頻濾波預測，各自的更新頻率與優先權
- [ ] 設計執行緒間資料交換機制（雙緩衝 double-buffer 或固定大小環形緩衝區），評估是否需要 lock-free 設計
- [ ] 研究即時性保證：Jetson 上是否需要調整執行緒排程優先權（`SCHED_FIFO`）、CPU 親和性（core pinning）
- [ ] 規劃系統啟動自檢流程（Pixhawk連線確認、相機連線確認、模型載入確認）與異常復原機制
- [ ] 規劃日誌記錄格式（時間戳、原始量測、濾波器狀態、姿態資料），供事後除錯與濾波器調參

## 7. 4G 模組與地面站通訊

- [ ] 確認 4G 模組型號與 Jetson/Pixhawk 的介接方式（USB modem、M.2、UART AT command）
- [ ] 研究 MAVLink over 4G 的封裝方式（例如 `mavlink-router` 或自建 UDP 轉發），並確認訊息優先權篩選（不要把高頻姿態灌爆頻寬）
- [ ] 設計降頻/降解析度的影像回傳策略（給地面站監看用，不進即時追蹤迴圈）
- [ ] 研究 4G 斷線時的容錯機制（自動切換備援鏈路、任務中斷後的行為定義）
- [ ] 評估延遲/掉包對「指揮層級」指令（如目標指定、任務更新）的影響，設計重傳與確認機制

## 8. 測試與驗證

- [ ] 建立 SIL（Software-In-the-Loop）模擬環境（ArduPilot SITL / PX4 SITL + Gazebo）先行驗證濾波器與座標轉換邏輯
- [ ] 規劃 HIL（Hardware-In-the-Loop）測試，讓 Jetson 接上真實 Pixhawk 硬體但飛行動態由模擬器提供
- [ ] 設計地面靜態測試：固定相機拍攝移動目標（如遙控車），驗證偵測+濾波器管線
- [ ] 規劃低速、低風險的初期試飛計畫，逐步驗證到高速情境
- [ ] 建立量化評估指標（追蹤誤差 RMSE、遺失重新鎖定時間、機動時的收斂時間）

## 9. 多機編隊即時影像與資料鏈網路（Mesh + 4G，仿 Link-16 概念）

> 適用情境：不是單機作業，而是多架無人機組隊，需要機對機即時共享追蹤資訊與影像

- [ ] 研究 Link-16 的分層資料設計概念（結構化戰術訊息優先於原始感測器資料），評估如何套用到自己的訊息格式設計
- [ ] 設計輕量追蹤訊息格式（目標位置/速度/信心值/時間戳、機身健康狀態），估算單則訊息大小與所需更新頻率
- [ ] 研究市售 MANET（行動隨意網路）電台產品（如 Silvus StreamCaster、Persistent Systems Wave Relay、Doodle Labs Mesh Rider 等），比較其 TDMA/OFDMA 機制、跳頻能力、實測頻寬/延遲/多跳表現
- [ ] 決定網路拓樸：純 Mesh vs. Mesh+4G 混合式，並定義何時該切換/併用哪條鏈路
- [ ] 研究 Mesh 常見自組路由協定（OLSR、BATMAN-adv 或電台廠商專屬協定），了解多機動態拓樸下的路由收斂速度
- [ ] 做頻寬預算試算：追蹤訊息 + 縮圖/ROI影像 + 原始影像三層資料，在不同機隊規模下的頻寬需求，確認不超過所選電台的實際可用頻寬（尤其節點增加時頻寬會被均分）
- [ ] 研究影像壓縮方案（H.264/H.265）在多節點同時傳輸下的可調位元率策略
- [ ] 規劃全機隊共同時間基準（可直接沿用各機 Pixhawk 的 GPS 授時），供多機協同追蹤/資料融合使用
- [ ] 研究資料鏈加密與認證機制，避免被竊聽或偽造追蹤資料注入機隊網路
- [ ] 確認 NCC 對所選頻段/發射功率的法規要求，評估軍規等級 MANET 電台在台灣民用申請上的限制

## 10. 法規與安全（台灣）

- [ ] 確認民航局（CAA）無人機相關法規，特別是 BVLOS（超視距）飛行的申請要求
- [ ] 確認飛行場域是否需要向地方主管機關或軍方協調空域
- [ ] 研究是否需要遙控無人機操作證、以及機型是否需要辦理型號檢驗
- [ ] 規劃失效保護（fail-safe）機制是否符合法規要求（如失聯自動返航、任務中斷程序）

## 機隊追蹤能力演進路線圖

**第一階段：各機獨立追蹤 + 資料共享（先做這個）**
- 每架機各自完整跑「偵測 → 濾波 → 目標狀態估計」，只把追蹤結果（位置/速度/信心值/時間戳）透過 mesh 廣播
- 地面站或其他機收到後做展示疊圖，或簡單的資料關聯（判斷不同機回報的是否為同一目標）
- 不涉及感測器層級融合，任一機故障不影響其他機運作，難度與風險相對低

**第二階段：多視角融合定位（進化目標）**
新增以下研究項目，這些是跟第一階段本質不同難度的部分：
- [ ] 精確跨機時間同步（誤差需求比單機系統嚴格得多，角度量測誤差會隨時間差放大）
- [ ] 各機自身定位精度需求評估（目標位置由多觀測點視線交會算出，觀測點自身位置誤差會直接傳遞放大到目標位置誤差）
- [ ] 研究多視角三角定位/融合演算法（如多平台 bearings-only tracking 的可觀測性理論、加權最小平方或融合濾波器）
- [ ] 決定融合架構：集中式（單一節點匯總全部量測做全域濾波）vs. 分散式/共識式（各機局部濾波器 + 共識演算法交換資訊），並評估某機失聯時的降級行為
- [ ] 規劃從第一階段平滑過渡到第二階段的資料格式相容性（避免屆時要整套重新設計訊息協定）
