這題超經典，但如果你真的搞懂它，你在 C++ 的抽象層次與效能思維上會直接升一階。
我們直接來開剖「靜態多型 (Static Polymorphism)」 vs 「動態多型 (Dynamic Polymorphism)」的核心差異、原理與應用場景。

🚀 一、基本定義對照

| 項目    | 靜態多型 (Static Polymorphism)    | 動態多型 (Dynamic Polymorphism) |
| ----- | ----------------------------- | --------------------------- |
| 發生時機  | 編譯期 (compile-time)            | 執行期 (runtime)               |
| 實現方式  | **模板 (templates)** 或 **CRTP** | **虛函式 (virtual functions)** |
| 綁定方式  | **靜態綁定 (static binding)**     | **動態綁定 (dynamic binding)**  |
| 執行效率  | 無虛擬表開銷，速度快                    | 經由 vtable 查表，有少許開銷          |
| 可擴充性  | 編譯期決定，不支援動態型別                 | 可動態決定型別，支援多型指標              |
| 記憶體負擔 | 無 vtable，較輕                   | 每個有虛函式的類別含 vptr             |


🧩 二、範例比較
✅ 動態多型例子（使用 virtual）

``` cpp
#include <iostream>
using namespace std;

class Animal {
public:
    virtual void speak() { cout << "Animal sound\n"; }
    virtual ~Animal() = default; // 別忘記虛析構
};

class Dog : public Animal {
public:
    void speak() override { cout << "Woof!\n"; }
};

void makeSound(Animal& a) {
    a.speak(); // 執行期由 vtable 決定呼叫哪個 speak()
}

int main() {
    Dog d;
    makeSound(d); // 執行期決定呼叫 Dog::speak()
}
```

🧠 說明：

- 編譯時不知道 a 具體是哪個型別。
- 執行期藉由「虛擬表指標 (vptr)」查表呼叫對應的函式。
- 有彈性，但多一層 indirection。

⚡ 靜態多型例子（使用 CRTP）

``` cpp
#include <iostream>
using namespace std;

// CRTP：Curiously Recurring Template Pattern
template <typename Derived>
class Animal {
public:
    void makeSound() {
        static_cast<Derived*>(this)->speak(); // 編譯期綁定
    }
};

class Dog : public Animal<Dog> {
public:
    void speak() { cout << "Woof!\n"; }
};

int main() {
    Dog d;
    d.makeSound(); // 編譯期已知呼叫 Dog::speak()
}
```

🧠 說明：

- 沒有 virtual，也沒有 vtable。
- 透過模板參數在編譯期決定具體類別。
- 編譯器可 inline 甚至最佳化掉整個呼叫鏈，零開銷。

⚔️ 三、優缺點對決

| 面向       | 靜態多型                       | 動態多型                   |
| -------- | -------------------------- | ---------------------- |
| **執行效率** | ✅ 快、可 inline               | ```❌``` 有 vtable 開銷          |
| **彈性**   | ```❌``` 編譯期決定型別                  | ✅ 執行期決定行為              |
| **擴展性**  | ```❌``` 新型別需重新編譯                 | ✅ 可用基類指標處理多種子類         |
| **程式體積** | 可能被模板展開膨脹                  | 相對精簡                   |
| **應用場景** | 效能導向（e.g. 數值計算、GPU kernel） | 架構導向（e.g. plugin、事件分派） |


🧠 四、底層視角

- 動態多型
    每個含虛函式的類別都有一個 vtable (虛擬函式表)，物件內部會藏一個指標（vptr）指向該表。
    呼叫虛函式時 → 編譯器產生 obj->vptr[n]() 查表呼叫。

- 靜態多型
    完全沒有 vptr 或 vtable，
    因為 Derived 類型在編譯期已確定，編譯器直接展開實際函式呼叫。

🧪 五、混合應用 (Hybrid Pattern)

有時你可以結合兩者：
例如在高效的推論系統中，你可以用 CRTP 提供靜態介面模板，但在最外層 plugin manager 用 virtual 提供動態切換模組能力。

``` cpp
template <typename Derived>
class FilterBase {
public:
    void process() {
        static_cast<Derived*>(this)->impl(); // 靜態多型
    }
};

class GaussianFilter : public FilterBase<GaussianFilter> {
public:
    void impl() { cout << "Gaussian\n"; }
};

// runtime polymorphism 封裝
class IFilter {
public:
    virtual void process() = 0;
    virtual ~IFilter() = default;
};
```

→ 這樣內層快、外層彈性強，算是高階 C++ 設計常見做法。

🎯 結論（一句話記住）
    🧩 靜態多型： 型別在「編譯期」決定，追求效能。
    🧩 動態多型： 行為在「執行期」決定，追求彈性。
